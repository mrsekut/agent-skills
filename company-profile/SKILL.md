# Company Profile

戦略論・経営書で繰り返し参照される事例企業を、後で再会した時に思い出せる形でメモ化するスキル。

事例カタログがあると、新しい本を読んだ時に「あ、これは前にメモったあの会社の話だ」と紐付けられて、情報の洪水が「既知パーツの再利用」に変わる。これを支援するのがこのスキル。

## いつ使うか

- 戦略論・経営本を読んでいて事例企業（例: スターバックス、フォード、サウスウェスト航空、トヨタ、ウォルマート）に遭遇した時
- 「〇〇についてメモして」「この会社まとめて」と頼まれた時
- 複数社を「〇〇と××と△△でまとめて」と頼まれた時

## やること

1. 各社について web 検索や手元の知識でリサーチする（年号は必ず検索で確認すること）
2. 下記の出力フォーマットに従って markdown ファイルを作成する
3. 1社1ファイル、ファイル名はユーザーが入力した社名をそのまま使う（例: `スターバックス.md`、`Ford.md`）
4. カレントディレクトリに保存する（出力先指定があればそちらへ）

## 出力フォーマット

```markdown
# {社名}

**何屋**: 一行で（業界 + その会社の代名詞的特徴）
**創業**: {年} / {都市・国} / **現状**: {存続/衰退/買収/倒産 + 一言コメント}

## ビジネスモデル
誰に何を売って、どこで儲けているかを 2-3行で。

## なぜ有名か（戦略論的な意義）
- 何の概念の事例として引かれるか（SP / OC / イノベーターのジレンマ / ジョブ理論 / 体験経済 など）
- どの本でよく登場するか
- 4-6項目以内に絞る

## タイムライン
- {年}: 創業 / 起点
- {年}: ブレイクのきっかけ
- {年}: ピーク
- {年}: 転機 / 没落のきっかけ（あれば）
- {年}: 現在
（5-7項目以内）

## 直感に反する面白いポイント
- 業界の常識と逆の打ち手 / "なぜそれで儲かるの?" な部分
- **3個まで** に厳選

## よく対比される企業
- A vs B の構図で覚えると効くやつ（2-4社）

## 出てくる本
- 書籍名（できれば章 or 概念も）
```

## 各項目の書き方ガイド

### 「何屋」
業界名だけでなく、その会社の代名詞的特徴を一行に込める。
- 弱い: 「米国のコーヒーチェーン」
- 良い: 「米国発のコーヒーチェーン。"第三の場所" を売る業態」

### 「現状」
存続/衰退の二択ではなく、ニュアンスを一言添える。
- 「存続するが業界1位ではない」
- 「2003年に倒産後、ブランドのみ存続」
- 「存続、世界80カ国超・3万8千店超」

### 「なぜ有名か」
**この項目が一番重要**。後で「あの会社、なんで有名だっけ？」と思い出すとき、ここだけ見れば足りるように書く。
- どの戦略論の概念の代表例なのか
- どの本でよく見るのか
- 複数の文脈で使われる場合は文脈ごとに分けて書く

### 「直感に反する面白いポイント」（最重要 + 厳選）
ここがメモの一番の価値。普通の Wikipedia ではこの切り口で書かれない。
- 業界の常識と逆の打ち手
- 「なぜそれで成立するの？」と思える部分
- 一見すると非合理だが全体としては合理的な打ち手
- **必ず3個まで** に絞る。多いと印象が薄まる
- 本当にそういう面白い点が薄い会社なら2個や1個でもよい（無理に作らない）

### 「よく対比される企業」
戦略論の事例は対比でセットになっていることが多い（フォード vs GM、スタバ vs ドトール、HP vs Apple、トヨタ vs フォード）。最初から書いておくと記憶が定着しやすい。

## 文体ルール

- 1項目は長くても2行以内に収める
- 短い箇条書きを積み重ねる（長文を書かない）
- 全体で A4 半ページ〜1ページ程度に収まる量を目安に
- 日本語で書く

## 複数社処理

「スタバとフォードでまとめて」のように複数指定された場合:
- 1社1ファイルで作成（合算ファイルにはしない）
- リサーチは並列で行うと早い（サブエージェントを使ってよい）

## リサーチソース

| 対象 | 優先ソース |
|---|---|
| 有名な事例企業の基本情報 | 既知の戦略論知識 + Wikipedia |
| 年号・最新動向 | Web検索で必ず確認 |
| 戦略論的文脈 | 既知の書籍・概念 + Web検索で補完 |

## 注意点

- 既に同名ファイルが存在する場合は、上書きするか追記するか確認する
- 年号は記憶ではなく **検索で確認** する。うろ覚えで書かない
- 「直感に反するポイント」を埋めるために無理やり面白い話を作らない。本当にないなら省略可
- 戦略論的に有名でない会社を依頼された場合は、「この会社は戦略論の文脈で有名ですか？」と一度確認する（このスキルは戦略事例向けに設計されている）
- ビジネスモデルとなぜ有名かが内容的にかぶりがちなので、ビジネスモデルは「儲け方」、なぜ有名かは「教科書での意義」と切り分ける
