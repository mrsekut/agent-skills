# 対話しながら読む本を Cosense に書く

`mental-model-book` は読むだけで済むぶん受動的になる。こちらは、ユーザーが自分で考え、コードを読みに行くことで理解させる。そのために1章ずつ書き、章ごとにユーザーとやり取りしてから次の章に進む。

中断や離席を前提にする。本の状態はすべて Cosense の**管理ページ**に置き、会話の記憶に頼らない。

## ページ構成

- **管理ページ**（AI が読み書きする）: `<本のタイトル> 管理`
- **章ページ**（ユーザーが回答を書き、AI が返信する）: `<本のタイトル> 第N章 <章タイトル>`

管理ページに書くもの:

- ゴール（この本を読み終えて何をしたいか）と、読者のレベルの見立て
- アジェンダ: 章ごとに、章ページへのリンク、状態（未着手 / 進行中 / 完了）、章のゴール（「この章を終えたら〇〇を説明・予測できる」の形）
- 理解の記録: 分かったこと、怪しいこと、誤解していたこと。章ごとに追記する
- 問いの調整メモ: 「抽象的すぎた」「簡単すぎた」など、問いへの反応
- 脱線の置き場: 気になったが今は追わない話

## ワークフロー

### 0. 開始時

- 新規なら、Cosense のプロジェクトを聞く
- 管理ページの URL を渡されたら、それを読んで状態から再開する。進行中の章があれば、その章ページを読んで手順4から続ける

### 1. 理解度のディスカッションとアジェンダの合意

`mental-model-book` の Phase 0〜2 と同じ進め方をする。ゴールを聞き、何往復かして理解度を測り、アジェンダを提案して合意を得る。対象のコードがあれば、ここで読んでおく。

その本を公開してよいかどうか（業務の内容を書いてよいか）も、ここで決める。

合意できたら管理ページを作る。全章をここで詳しく決めすぎない。後の章は前の章の理解を見て組み直す前提で、各章のゴールを1行で書いておけば足りる。

### 2. 章を書く

1章は日本語で 1500〜2500字程度。解説と問いを混ぜる。

- 解説の書き方は `mental-model-book` の「執筆のルール」に従う（図、具体例、用語の初出、動機→仕組み の順）
- 問いは解説の流れの中、その問いを考えるのに必要な説明の直後に置く
- 第2章以降は、管理ページの「理解の記録」を踏まえる。前の章で怪しかった点を冒頭で回収してから本題に入る

ローカルに md を書き、`md2cosense` で投稿する（衝突確認などの手順は `book-to-cosense` に従う）。投稿したら、管理ページのアジェンダにある章の状態とリンクを更新する。

### 3. ユーザーが読んで回答する

ユーザーは問いの下にインデントして回答を書き、ターミナルで「書いた」などと伝える。AI から Cosense をポーリングしない。

### 4. 回答を読んで返す

章ページを読み、前回からの差分を見る（`cosense` スキルの `browsePageChanges`）。返信は回答行の子行として書く。AI の発言には、そのプロジェクトで使われている AI を指すアイコン記法を付ける。無ければ `[claude.icon]` を使う。

- 合っていれば、短く認め、補足があれば1〜2行添える
- 外れていたり浅かったりしたら、問いを1つ返す
- **1つの問いにつき、問い返しは2往復まで**。それで届かなければ解説して先に進む
- 回答の中に章のゴールから外れる疑問があれば、管理ページの「脱線の置き場」に移し、章ページでは「あとで」と一言返す

ターミナルには、何に返信したかを短く報告する。章ページへの書き込みは、このスキルの起動をもってユーザーの指示とみなす。内部リンクは章ページ同士と管理ページへのリンク以外は張らない。

返したら、管理ページの「理解の記録」と「問いの調整メモ」を更新する。

### 5. 章を閉じる

章のゴールがほぼ満たせたと判断したら、ターミナルで「ゴールはほぼ満たせた。怪しいのは△△」と伝える。次に進むかはユーザーが決める。進むなら章の状態を完了にして手順2へ。

全章が終わったら、管理ページに本全体の振り返り（最初の見立てからどう変わったか）を書いて終了する。

## 問いの作り方

問いがこのスキルの核になる。

- **1章あたり2〜4問**。どれも章のゴールに直結させる。章のゴールを満たすのに要らない問いは削る
- **入口はこちらから渡す**。ファイル名と関数名まで示し、問うのは読んで考える部分だけにする
- 次のような問いは書かない。時間を取るだけで理解につながらない
  - 「リポジトリからこの処理を探して」のような、探させる問い
  - 「ネットでこれを調べて」のような、調べさせる問い
  - 名前や数値を覚えているかを確かめるだけの問い
- 効きやすい型
  - 挙動の予測: 「この関数に〇〇が来たらどうなるか」
  - 理由: 「なぜここで〇〇しているのか。無かったら何が壊れるか」
  - 対応づけ: 「解説の△△は、このコードのどこに当たるか」
  - 比較: 「AとBで扱いが違うのはなぜか」
- 抽象度は最初は中くらいにし、「問いの調整メモ」を見て章ごとに寄せる。ユーザーが「難しすぎ」「抽象的すぎ」と言ったら、次の問いからすぐ反映する

## チェックリスト（章を投稿する前）

- [ ] どの問いにも入口（ファイル・関数）を示したか。探させる・調べさせる問いになっていないか
- [ ] 第2章以降で、前の章の「怪しいこと」を回収しているか
